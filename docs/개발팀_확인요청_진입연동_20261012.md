# 훈감각익히기 연동 — 개발팀 확인/요청 사항

- 작성: 2026-10-12 (study-force)
- 배경: 연동 문서 2종(진입 데이터 / 훈련완료 API v3) 검토 중 확인 필요 사항

---

## 1. 진입(배포) 주소 일원화  ★ 가장 중요

현재 훈감각익히기 앱이 **3곳**에 동시에 떠 있고, 셋 다 **같은 운영 DB(word-master)** 를 봅니다.

| 주소 | 호스팅 | 용도(우리 기준) |
|---|---|---|
| `word.sfcenter.co.kr` | Vercel | **실섭(운영)** |
| `word.sfos.kr` | Vercel | **테섭(테스트)** |
| `study-force.github.io/word-sense/` | GitHub Pages | — |

**요청**: 학생 진입 주소를 **실섭 `word.sfcenter.co.kr`**(테스트는 `word.sfos.kr`)로 통일하고,
**`study-force.github.io/word-sense/`(GitHub Pages)는 진입 경로에서 제외**하고 싶습니다.

- **(1-1)** 현재 학원 시스템은 학생을 **실제로 어느 주소**로 보내고 있나요? (연동문서엔 진입 URL이 GitHub Pages로 기재되어 있습니다.)
- **(1-2)** 진입 주소를 `word.sfcenter.co.kr`로 변경 가능한가요? GitHub Pages 배포는 중단/미사용해도 되나요?

## 2. 진입 데이터 전달 방식 (POST vs 세션토큰)

- 연동문서(진입 데이터)에는 진입 시 **JSON `POST`** 로 학생 정보 전달로 되어 있습니다.
- 그런데 정적 호스팅(GitHub Pages·Vercel 정적)에서는 페이지의 JS가 **POST 본문을 직접 읽을 수 없습니다.**
- **확인**: 실제 전달 방식이 POST 본문인가요, 세션토큰(`?st=`)/쿼리 방식인가요?
  `word.sfcenter.co.kr`로 통일 시 진입 데이터가 앱까지 **어떤 흐름으로 도달**하는지(처리 주체 포함) 알려주세요.

## 3. 훈련 완료 기록 — 두 경로 중복 여부

- ① 완료 API `POST /api/public/hanja/study/complete` → 레거시 `sf_study_hanja`
- ② 우리 앱이 Supabase(`attempts` 등)에 저장

→ **둘 다 호출**하는 게 맞나요? 역할이 (레거시 = 학원관리/정산, Supabase = 앱 상세통계)로 분리되는 게 맞는지 확인 부탁드립니다.

## 4. 선생님용 결과지 — 진입(접근) 연동

- 결과 데이터(영역별 습득 어휘·통과 회차·PERFECT·통계)는 **우리 Supabase에서 직접 조회**합니다.
  (레거시 DB엔 회차 완료 여부만 있어 상세 통계가 없음) → 읽기 소스는 별도 확인 불필요.
- **요청**: 선생님이 **학원 관리 시스템 안에서 학생을 클릭**하면 우리 결과지(팝업)가 뜨도록 연동하려 합니다.
  우리 결과 페이지를 **`user_no`로 여는 링크 연동**(진입 키 `user_no`, URL 형식)을 맞춰주실 수 있나요?

## 5. training_round → 콘텐츠 매핑

- 진입 시 받는 `training_round`로 **어떤 영역/회차 콘텐츠를 로드**해야 하는지 매핑 규칙이 필요합니다. (현재 앱은 매핑이 없어 항상 "생물 1회차"만 로드)
- **요청**: 회차 ↔ (영역, 회차번호, 과정) 매핑 규칙/표를 제공해 주실 수 있나요?

## 6. 인증 Secret

- 완료 API용 `X-External-Secret`(Secret Key) 공유 부탁드립니다. (상용 `:8143` / 개발 `:8193`, 필요 시 각각)

## 7. 테스트 환경 구축

- 테섭(`word.sfos.kr`) + 테스트 DB 구축 관련: 우리 쪽 Supabase 개발 프로젝트를 쓰면 되는지,
  레거시(service-back) **개발 서버(`:8193`)** 접근/테스트 방법은 어떻게 되나요?

### 참고 (우리 쪽 확정 사항)
