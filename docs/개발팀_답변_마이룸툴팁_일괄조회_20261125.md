### 2-1. 회차 줄(`items`)에 덧붙인 칸

| 값 | 내용 |
|---|---|
| `is_perfect` | 회차 어휘를 **모두 획득**했으면 `true` → 화면의 "perfect" |
| `passed` | **통과** 여부 — 회차 어휘의 80% 이상 획득 (실력 점검 응시 자격과 같은 기준) |
| `retrieve` | **인출** 어휘 `{ acquired, total }` — 스스로 떠올린 어휘 수 / 그날 훈련한 어휘 수 |
| `expand` | **확장** 어휘 `{ acquired, total }` — 확장 카드를 본 뒤 다시 떠올린 어휘 수 / 인출에서 못 떠올린 어휘 수 |
| `reinforce` | **강화** 어휘 `{ acquired, total }` — 한 번에 맞힌 어휘 수 / 강화에 나온 어휘 수 |
| `stage_source` | `words` = 어휘별 기록으로 계산(정확) / `summary` = 요약 숫자로 계산(옛 기록 — 이때 `reinforce`는 `null`) |
| `started_at` / `ended_at` | 훈련 **시작 시각 / 종료 시각** (종료 = 결과 화면에 닿은 때). 시각은 모두 UTC이니 한국 시간으로 바꿔 보여 주세요(+9시간) |
| `duration_sec` | 훈련에 걸린 시간(초) |
| `last_trained_at` | 가장 최근에 끝까지 한 훈련(재도전 포함)의 종료 시각 |
| `completed_at` | 훈련완료 API(엔드데이트)를 보낸 시각 — 아직 안 보냈으면 `null` |

- **인출·확장·강화·시작·종료 시각은 그 회차의 '첫 훈련' 기준입니다.** 재도전은 남은 어휘만 다시 하기 때문에, 섞으면 "인출 2/4"처럼 회차 전체와 맞지 않는 숫자가 됩니다.
- **총 획득어휘**는 지금 쓰시는 `acquired` / `total_words` 그대로입니다(재도전까지 합친 누적). 재도전으로 획득이 늘면 `acquired`만 늘고 `retrieve`·`expand`·`reinforce`는 그대로입니다.
- 강화의 `acquired`가 그날 새로 획득한 어휘 수입니다(인출이나 확장에서 떠올리고, 강화에서 한 번에 맞힌 어휘).
- 아직 끝까지 한 적이 없는 회차(하다 만 회차)는 이 칸들이 `null`입니다. `null`이면 "-"로 보여 주세요.
- 마이룸 표의 **훈련일시**는 `started_at`(첫 훈련) 또는 `last_trained_at`(가장 최근) 중 화면에 맞는 것을 쓰시면 됩니다. **반복횟수**는 지금의 `retry_count`입니다.

### 2-2. 실력 점검(`unit_tests`)

5회차 묶음마다 한 줄입니다(1~5회차 = 1차, 6~10회차 = 2차 …). **`after_round` 회차 줄 바로 아래**에 「실력점검」 줄을 그리시면 됩니다.

| 값 | 내용 |
|---|---|
| `unit` | 몇 번째 묶음인지 (1 = 1~5회차) |
| `round_from` / `round_to` / `after_round` | 묶음의 첫 회차 / 끝 회차 / 줄을 그릴 자리(= 끝 회차) |
| `trained_rounds` / `passed_rounds` | 묶음 5회차 중 훈련한 회차 수 / 통과(80% 이상 획득)한 회차 수 |
| `eligible` | 응시 가능 — 5회차를 **모두 통과**했을 때 `true` |
| `status` | `done`(본 적 있음) / `in_progress`(풀다가 멈춤) / `ready`(볼 수 있는데 아직 안 봄) / `locked`(아직 못 봄) |
| `question_count` | **문항 수** (본 적 없으면 `null` — 보통 25문항) |
| `score` / `max_score` | **총 점수** / 100 — 여러 번 봤으면 **가장 높았던 점수** (학생 화면의 훈사전에 보이는 점수와 같음) |
| `mastered_count` / `mastered_score` | **완전 습득** — 한글만 보고 맞힌 문항 수 / 그 점수 (문항당 4점) |
| `inferred_count` / `inferred_score` | **추론** — 한자를 보고 맞힌 문항 수 / 그 점수 (문항당 2점) |
| `wrong_count` | 틀린 문항 수 |
| `try_count` / `retry_count` | 끝까지 본 횟수 / **반복 횟수**(= 본 횟수 − 1) |
| `first_score` / `last_score` | 처음 본 점수 / 가장 최근 점수 |
| `started_at` / `ended_at` | `score`를 받은 응시의 시작 / 종료 시각 |

- `mastered_score + inferred_score = score` 입니다. (예: 완전 습득 92 + 추론 4 = 96점)
- 묶음의 회차를 하나라도 훈련했으면 줄이 들어 있습니다. 5회차를 다 하기 전에는 `status: "locked"`이니, 표에는 `after_round` 회차가 있을 때만 그리시면 됩니다.
- **실력 점검을 `items`에 넣지 않고 따로 담은 이유:** 지금 화면이 `items`를 한 줄씩 '회차'로 그리고 계셔서, 같은 목록에 실력 점검 줄이 섞이면 회차로 잘못 그려질 수 있기 때문입니다. `unit_tests`를 읽지 않으시면 화면은 지금과 똑같습니다.

## 3. 여러 학생 한 번에 조회 (전체훈련현황)

**요청 ① — 같은 과정·영역의 학생들**

```json
{ "action": "rounds", "user_nos": [88660, 88661, 88662], "training_level": "elementary", "training_area": "science" }
```

**요청 ② — 학생마다 과정·영역이 다를 때** (한 학생이 여러 영역을 훈련하면 그 수만큼 넣어 주세요)

```json
{ "action": "rounds", "targets": [
    { "user_no": 88660, "training_level": "elementary", "training_area": "science" },
    { "user_no": 88660, "training_level": "elementary", "training_area": "biology" },
    { "user_no": 88661, "training_level": "middle",     "training_area": "history" }
] }
```

**응답** — 회원번호별로 묶어 드립니다. 안쪽 `items`·`unit_tests`는 2번과 똑같은 모양입니다.

```json
{
  "success": true,
  "count": 3,
  "students": {
    "88660": [
      { "training_level": "elementary", "training_area": "science", "items": [ … ], "unit_tests": [ … ] },
      { "training_level": "elementary", "training_area": "biology", "items": [ … ], "unit_tests": [ … ] }
    ],
    "88661": [
      { "training_level": "middle", "training_area": "history", "items": [], "unit_tests": [] }
    ]
  }
}
```

| 값 | 내용 |
|---|---|
| `user_nos` | 회원번호 목록 — `training_level`, `training_area`를 함께 보내 주세요(모든 학생에게 같이 적용) |
| `targets` | (학생, 과정, 영역) 묶음 목록 — 묶음에 과정·영역이 없으면 바깥의 `training_level`·`training_area`를 씁니다 |
| `students` | 열쇠 = 회원번호(문자), 값 = 요청한 (과정·영역)별 결과 목록 |
| `count` | 조회한 묶음 수 |

- **한 번에 60개 묶음까지**입니다(학생 50명 한 쪽이면 한 번). 넘으면 `400`·`code: "too_many"`가 오니 나누어 불러 주세요.
- 기록이 없는 학생도 빈 목록(`items: []`)으로 들어 있습니다. 요청한 학생은 모두 응답에 있습니다.
- 같은 묶음을 두 번 넣으셔도 한 번만 계산합니다.
- 회원번호가 숫자가 아니거나 영역 이름이 틀리면 전체가 `400`으로 돌아옵니다.
- `user_nos`·`targets`가 없으면 지금처럼 학생 한 명 조회(2번)로 움직입니다.
- 서버에서 학생 수와 상관없이 **조회 2번**으로 끝나므로, 50번 나누어 부르시는 것보다 훨씬 가볍습니다. 전체훈련현황은 **쪽을 열 때 한 번**만 불러 주세요.

## 4. 오류 응답

| 상태 | `code` | 뜻 |
|---|---|---|
| 400 | `too_many` | 한 번에 60개를 넘음 — 나누어 불러 주세요 |
| 400 | – | `user_no`가 숫자가 아님 / `training_area`가 틀림 |
| 401 | `bad_key` | (나중에 조회 열쇠를 쓰게 되면) 열쇠가 맞지 않음 — 지금은 열쇠 없이 쓰실 수 있습니다 |
| 503 | `batch_unavailable` | 여러 학생 조회를 잠시 쓸 수 없음 — 학생 한 명씩 불러 주세요 |

## 5. 참고 — 실력 점검이 지금 움직이는 방식

정책 답변은 대표님 확인 뒤 드리고, 지금 프로그램의 동작만 적습니다.

- 실력 점검은 **자동으로 시작하지 않습니다.** 학생이 훈련 결과 화면에서 [나의 훈사전 보기]로 들어가면, 5회차 줄 옆에 「실력 점검」 칸이 있고 그 칸을 눌러야 시작합니다.
- **훈련완료 API(엔드데이트)는 [나의 훈사전 보기]를 누르는 순간** 보냅니다(11월 2일 안내와 같음). 그래서 5회차의 훈련완료 API가 **실력 점검보다 먼저** 갑니다.
- 5회차 중 **통과(80% 이상 획득)하지 못한 회차가 있으면** 실력 점검 칸이 잠겨 있습니다(`eligible: false`). 재도전으로 80%를 채우면 열립니다.
- 실력 점검을 보지 않아도 **다음 회차 훈련은 막지 않습니다.** 어느 회차를 열지는 지금처럼 학원 쪽에서 보내 주시는 `training_round`를 따릅니다.
- 실력 점검은 훈련완료 API를 부르지 않고 `study_token`도 쓰지 않습니다.
- 지금은 **마이룸에서 실력 점검만 바로 여는 입장 방식이 없습니다**(훈련 화면 안의 훈사전에서만 시작). 마이룸 표에 [실력점검] 버튼이 필요하면 저희 쪽에 입장 방식을 새로 만들어야 합니다.
